## 二、本轮同时修掉的 6 类缺陷

抽取过程中暴露出 6 个会**直接导致构建失败、测试全红或线上功能异常**的问题，已一并修复。
其中第 5、6 条**只有真正跑起来才会暴露**，只做静态检查永远发现不了。

### 1. 生成的 `S` 方法签名与调用点不匹配（构建必失败）

全项目 800+ 处调用点写成命名参数形式：`appLoc.s_0e59d960(y: y, m: m)`。
而 `gen-l10n` **默认生成位置参数**。若不配置，全项目会大面积编译失败。

修复：`app/l10n.yaml` 增加

```yaml
use-named-parameters: true
```

开启后生成 `String s_0e59d960({required Object y, required Object m})`，与调用点一致。

> **关于版本要求（已实测更正）**：本文早期版本曾断言该选项「Flutter ≥ 3.29 才加入 gen-l10n，
> 低版本会被静默忽略」——**这是错的，已作废**。经在本机 WSL 的
> **Flutter 3.24.5 / Dart 3.5.4** 上实跑 `flutter gen-l10n`，
> `use-named-parameters: true` **生效正常**，生成的确是
> `String s_0e59d960({required Object y, required Object m})` 这样的命名参数签名
> （由 SDK 内 `localizations_utils.dart` 源码与生成产物双向确认）。
> 结论：**3.24.5 及以上都能用**，Codemagic 的 `flutter: stable` 自然也满足。
> 之所以当初会误判，是因为只在 Windows 侧做静态检查、没有真正跑过 Flutter——
> 这正是必须走 WSL 实跑的原因（见第三节）。

### 2. 提示词里的字面大括号会让 ICU 解析器直接报错

4 条大模型提示词内嵌 JSON 示例（如 `{"title":"书名",...}`）。
严格语法下 ICU 解析器报 `Expected "identifier"` 并**中断构建**。

修复：`l10n.yaml` 增加

```yaml
relax-syntax: true
```

**关键副作用**：开启后"合法占位符"只认 `app_en.arb` 中 `@key.placeholders` **显式声明**过的名字，
未声明的 `{xxx}` 会被当成普通文本（静默失效）。因此本轮已为全部 152 条含占位符的消息补齐声明：

```json
"@s_c94c96fc": {
  "description": "auto-extracted",
  "placeholders": { "apiError": {} }
}
```

### 3. 分类词表被本地化，导致英文用户数据分裂（严重）

抽取时把 `models/enums.dart` 的 `defaultCategories` / `categoryAliases` **值**也换成了 `appLoc.*`。
但由于这些字符串是写进数据库 `categoryPrimary` 字段的**规范值（canonical）**，后果是：

- 38 本内置示例书（`assets/seed/library.json` 里是中文分类）在英文设备上**全部归入「其他」**；
- 用户切换一次语言，同一批书会裂成「文学」与「Literature」两组，统计图表与画像全部失真；
- 分类下拉框会往库里写英文值，与历史数据混在一起。

修复：**规范值恢复为与语言无关的固定字面量**（仍用中文，避免存量数据迁移），
显示统一走新增的 `categoryLabel()`：

```dart
const List<String> defaultCategories = ['文学','社科','历史', ...];  // 数据，不翻译
const String kUncategorized = '未分类';                              // 兼作 Map key
String categoryLabel(String canonical) => ...;                      // 规范值 -> 当前语言
```

同时：

- 修正 `data/reading_profile.dart` 中 **37 处** `cat()/catShare()/pct()` 与 **18 处** `strong()`
  误传本地化名作 map key 的调用；
- 修正 4 处 `?? appLoc.s_363c6a0c`（「未分类」被当 map key）为常量 `kUncategorized`；
- `data/database.dart` 的 `COALESCE(categoryPrimary,'未分类')` 回到内联字面量，
  与 Dart 侧 `categoryDistributionOf` 保持同一 key；
- 分类展示点（书架徽标、图书详情、统计图表与图例、分类下拉）统一经 `categoryLabel()` 输出；
- `categoryAliases` 补充 **60+ 条英文原始分类**（Goodreads / Open Library 常见层级名），
  并改为**按 key 长度降序**做包含式兜底，避免 `"Nonfiction > Philosophy"` 被 `Fiction` 抢先命中。

### 4. 字面 `\n` 与非法占位符名

- **15 条**消息里是两个字面字符 `\`+`n` 而非真换行（源自单引号 Dart 字符串的 `\n`），
  界面会直接显示 `\n`。已全部转为真实换行。
- **3 个占位符名非法**：`_unratedCount`、`_reportCount`（下划线开头，Dart 命名参数不允许）
  与 `library`（易与关键字混淆）。已重命名为 `unratedCount` / `reportCount` / `libraryCount`，
  并同步修改调用点。
- 顺带修掉 **2 处** `const DropdownMenuItem(... Text(appLoc.xxx))`：`appLoc` 是运行时 getter，
  放进 `const` 构造是非法的。同时删除了 **53 条**因规范值回归而失效的分类别名词条。

### 5. 首次启动必崩：本地化还没就绪就去初始化数据库（线上阻断级）

WSL 里把测试跑起来后，报错不是「测试写错了」，而是：

```
StateError: appLoc accessed before localization init
  ...
  main() → AppDatabase.instance.init() → 迁移/灌种子 → categoryLabel() → appLoc
```

根因在 `lib/main.dart` 的启动顺序：

```dart
// ❌ 原来：init() 里会走 categoryLabel()，而 appLoc 此时还没装
await AppDatabase.instance.init();
runApp(...);

// ✅ 现在：先把本地化装好，再动数据库
setAppLoc(await S.delegate.load(WidgetsBinding.instance.platformDispatcher.locale));
await AppDatabase.instance.init();
runApp(const ProviderScope(child: ReadingTrackerApp()));
```

这不是测试环境的问题——**真机首次安装启动就会以同样方式崩掉**（迁移 + 灌 38 本种子书时必然触发
`categoryLabel`）。也就是说，如果只做静态检查直接打包上架，用户装完打开就是闪退。

### 6. 测试全线飘红：`appLoc` 未初始化 + `MaterialApp` 缺 `S.delegate`

修完第 5 条后仍有 140 项失败，分两类：

| 数量 | 症状 | 原因 |
|---|---|---|
| 138 | `StateError: appLoc accessed before localization init` | 纯逻辑测试（DB / 统计 / 归一化）从没经过 `runApp`，`appLoc` 永远是空的 |
| 2 | `_TypeError` at `app_localizations.dart:70`（`S.of(context)!` 拿到 null） | `screenshot_test.dart` / `ui_pages_test.dart` 自建 `MaterialApp` 时没挂 `S.delegate` |

修复（新增两个测试基建文件，不改任何业务代码）：

- `test/flutter_test_config.dart` —— Flutter 测试的全局钩子。在**所有**测试跑之前
  强制语言为 `zh`、并把 `appLoc` 预热好：

  ```dart
  Future<void> testExecutable(FutureOr<void> Function() testMain) async {
    final binding = TestWidgetsFlutterBinding.ensureInitialized();
    binding.platformDispatcher.localeTestValue = const Locale('zh');
    binding.platformDispatcher.localesTestValue = const <Locale>[Locale('zh')];
    setAppLoc(await S.delegate.load(const Locale('zh')));
    await testMain();
  }
  ```

- `test/support/localized_app.dart` —— 给 Widget 测试用的 `localizedApp(...)` 助手，
  挂全 `S.delegate` + `GlobalMaterialLocalizations` 等委托，并在 `builder` 里
  调 `setAppLoc(S.of(ctx))`，**与 `main.dart` 的行为保持一致**，避免测试和生产两套语义。

结果：`150 → 310` 项全部通过。

> 附带教训：测试里不要用 `pumpAndSettle`，UI 测试必须用
> `databaseFactoryFfiNoIsolate`（原因见 `04-WSL开发环境与继续开发指南.md` 的「坑」）。


本机 WSL（Ubuntu 24.04，Flutter 已装在 `~/dev/flutter`）直接用工程自带脚本一次跑完 2→5 步：

```bash

```

`scripts/verify_wsl.sh` 的流程：`pub get` → `analyze` → `test` → `build bundle`（`--quick` 可跳过打包）。
本轮（2026-10-01）该脚本的实测结果：

| 步骤 | 结果 |
|---|---|
| 依赖解析 | `Changed 111 dependencies!` ✅ |
| 静态分析 | `No issues found! (ran in 4.5s)` ✅ |
| 单元测试 | `00:38 +310: All tests passed!` ✅ |
| 资源打包（验证 Dart 编译） | `{"assets/seed/library.json":["assets/seed/library.json"]}` ✅ |

`verify_i18n.py` 会检查 6 件事：zh/en 键集合一致、`@@locale` 正确、每条含占位符的消息都已声明
占位符、所有 `appLoc.<key>` 调用点的命名实参与占位符**完全对应**、不存在 `const` 包裹 `appLoc`
的非法写法、分类函数实参没有被本地化文案污染。任何一项不通过都会以非零码退出，适合挂进 CI。

> **解析器本身的两个坑（已修）**：
> 1. **必须先剥离注释再找调用点**。脚本早期版本直接扫原始源码，
>    结果把 `stats_page.dart` 里一句**注释**`// 默认值不能是 appLoc.xxx`当成了真实调用，
>    误报「引用了不存在的键 xxx」。现已改为先把注释/字符串替换成**等长**空白
>    （等长是为了不破坏行号计算），再扫描。
> 2. **死键判定不能用子串匹配**。键 `openLibraryImport` 是 `openLibraryImportDesc` 的前缀，
>    用 `'.openLibraryImport' in src` 判定会把前者误判成已引用。
>    现改用带标识符边界的正则 `(?<![A-Za-z0-9_])key(?![A-Za-z0-9_])`。
>    同时**必须排除生成的 `app_localizations*.dart`**——那三个文件声明了每一个键，
>    纳入扫描会让死键检查形同虚设。
>
> 修正后实测：`617 消息 / 153 含占位符 / 613 调用点键 / 死键 0`，全部通过。

`pubspec.yaml` 已加入：

```yaml
flutter:
  generate: true   # 缺这一行就必须每次手动 flutter gen-l10n
```

`l10n.yaml` 现状：

```yaml
arb-dir: lib/l10n
template-arb-file: app_en.arb        # 英文是模板，新文案请先加这里
output-localization-file: app_localizations.dart
output-class: S
nullable-getter: false
synthetic-package: false             # 仅兼容旧 SDK；>=3.32 会打印一条无作用警告
use-named-parameters: true           # 生成命名参数签名，勿删（3.24.5 实测可用）
relax-syntax: true                   # 容忍提示词里的 JSON 大括号，勿删
```

> 注意：`synthetic-package: false` 在 Flutter ≥ 3.32 会打印
> "no longer has any effect and should be removed" 的**警告**（不是错误）。
> 保留是为了兼容更旧的 SDK，可在确认全员升级后删除。

## 四、工程约定（改文案前请先读）

1. **新增文案先加 `app_en.arb`**（它是 `template-arb-file`），再补 `app_zh.arb`，两边键名必须一致。
2. **含占位符的消息必须在 `@key.placeholders` 里声明**。因为开了 `relax-syntax: true`，
   没声明的 `{xxx}` 会静默变成普通文本——不报错，只是界面显示 `{xxx}`。
   占位符名不得以下划线开头，也不要用 Dart 关键字。
3. **界面里不要直接显示规范分类值**，一律经 `categoryLabel()`。
4. **正则 / 括号集合 / SQL 片段属于数据，不要翻译**：中英必须逐字相同。
5. 非 Widget 上下文（枚举 getter、导入解析器、AI 客户端、Provider）用全局 `appLoc.<key>`；
   有 `BuildContext` 时用 `S.of(context)` 或 `l10n.<key>`。三者等价。
6. `app/l10n/app_loc.dart` 不在任何备份里，如整目录回滚需手动重建。
