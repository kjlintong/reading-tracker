# Global readiness review

本文档记录面向英文、美国和欧洲用户的产品与架构建议。iOS 不在当前范围内；本文不把 iOS 发布列为近期工作。

## 已实施的界面基础优化

- 统一 Material 3 的纸张感浅色背景与克制的深色背景，保留现有主题色、明暗模式和主题选择。
- 统一 AppBar、卡片、输入框、按钮、对话框、底部抽屉和底部导航的圆角、边框、间距与触控尺寸。
- 调整全局文字层级，避免页面标题和正文依赖局部硬编码样式。

这些改动只涉及视觉主题，不改变数据库、领域模型或现有功能流程。

## P0：发布前必须核对

### 1. 隐私说明与真实数据传输保持一致

当前文档对 AI 阅读报告和 OCR/图片处理的数据范围存在需要进一步对齐的表述：README 更强调标题、笔记不上传，而隐私政策又描述了报告请求可能包含变更图书的标题、作者等信息。应以实际网络请求为准，逐个功能列明：

- 哪些功能完全离线；
- 元数据搜索会把哪些查询发给 Google Books、Open Library 或其他提供方；
- AI 报告是否发送标题、作者、阅读记录、笔记或统计摘要；
- 图片是否离开设备，以及保留时间、第三方接收方和用户撤回方式。

在设置页和首次启用在线功能时显示简短、可操作的说明，并提供隐私政策全文入口。不要用“不会上传数据”这种无法覆盖所有可选功能的绝对表述。

### 2. 备份与恢复成为可发现的核心能力

产品是本地优先架构，没有账户和云同步。JSON 备份是正确的低依赖方案，但设备损坏、换机或卸载会造成用户误以为数据丢失。建议：

- 首次使用后提示用户创建备份，而不是只把入口放在设置深处；
- 在备份页显示最近一次导出时间和数据范围；
- 恢复前明确“合并/覆盖”的行为，并显示版本兼容性；
- 增加真实数据的导出—导入往返测试和数据库迁移测试；
- 备份文件中保留 schema/version 字段，便于未来迁移。

### 3. 对 Goodreads 导入的产品承诺要准确

商店文案提到 Goodreads，而当前产品还依赖 CSV/导入流程。需要明确它是“导入 Goodreads 导出的 CSV”，还是计划中的直接接口；不要让用户误以为存在 Goodreads 官方实时同步。CSV 导入应展示字段映射、跳过原因、重复项处理和最终导入数量。

## P1：国际用户体验

### 4. Locale、日期、周起始日和时区

界面已有英语、德语、法语、西班牙语和中文资源，但翻译完成不等于本地化完成。应覆盖：

- en-US 与 en-GB 的日期、数字和周起始日；
- 欧洲小数分隔符、长月份名和长按钮文案；
- 夏令时切换附近的阅读记录和提醒；
- 设备时区变更后的历史日期显示；
- 大字号和窄屏下的标签、筛选器、图表与底部抽屉。

日期数据应继续存储可迁移的时间值，显示时使用当前 locale/timezone，避免把显示字符串写入数据库。

### 5. 元数据提供方与导入器保持可替换

Google Books 和 Open Library 适合作为第一批国际目录，但两者的覆盖、地区版本、封面和作者格式并不一致。建议保持明确的 provider 接口：查询、详情、封面、限流/错误分类分别建模；将 provider 名称、原始 ID 和原始响应必要字段保存下来，避免同一本书重复匹配。

分类和作者规范化不能假设中文或拉丁字母：需要覆盖重音符号、多个作者、连字符、CJK、阿拉伯文字和同名书。显示标签可本地化，但导入匹配键应保留稳定的原始值。

### 6. 明确在线/离线状态

搜索、在线元数据、可选 AI 服务和本地 OCR 应在界面上区分。错误提示应说明是网络不可用、服务限流、没有配置 endpoint，还是结果为空；本地书架、笔记、统计和备份应明确标记为离线可用。

## P2：架构演进建议

- 给导入流程统一返回结果模型：成功、重复、需要确认、跳过、失败，并带用户可读原因。
- 为外部服务设置统一超时、重试和限流策略，不让 UI 直接感知 provider 的异常类型。
- 把在线请求审计为可测试的 payload builder，便于隐私审核和未来增加服务商。
- 为数据导出格式写版本化 schema 与迁移测试，而不是只依赖当前数据库表结构。
- 在 CI 中固定 Flutter/Dart 支持范围，并把 gen-l10n 配置和构建文档中的最低版本统一。

## 暂不做

- iOS/App Store 发布与 Apple 平台适配，按当前产品决策暂缓。
- 没有明确用户需求前，不增加账户、社交、云同步或更多 AI 服务；这些会显著扩大隐私、运维和数据迁移成本。
