## 一、P0 — 阻断上架（不改则无法过审）

### P0-1　iOS 端实质缺失，权限声明为零

最新代码 `_stage/app` **没有 `ios/` 目录**；`reading-tracker/app` 中的 `ios/` 是 Flutter 模板默认产物。具体缺陷：

| 项 | 现状 | 后果 |
|---|---|---|
| `Info.plist` 相机/相册用途声明 | **缺失** `NSCameraUsageDescription`、`NSPhotoLibraryUsageDescription` | 调用拍照导入/相册选图时 **进程直接崩溃**；Apple 审核必拒（Guideline 5.1.1） |
| `IPHONEOS_DEPLOYMENT_TARGET` | `12.0` | `google_mlkit_text_recognition` 对应 ML Kit 要求 **iOS ≥ 15.5**，编译即失败 |
| `PrivacyInfo.xcprivacy` | **不存在** | 2024-05 起 App Store 强制要求隐私清单，缺失将触发提审拦截 |
| `Podfile` | 不存在 | 需 `pod install` 才能拉取 ML Kit 原生库 |
| 多语言声明 | `Info.plist` 未声明 `CFBundleLocalizations` | 即使做了 i18n，商店也不会展示为多语言应用 |

> **硬性约束**：iOS 产物必须在 macOS + Xcode 环境构建，当前 WSL 通道无法产出。这是发布路径上的一个独立前置条件，需要单独准备（Mac 设备 / 云 Mac / GitHub Actions macOS runner）。

### P0-2　Android 发布配置未就绪

`reading-tracker/app/android/app/build.gradle`：

```gradle
defaultConfig {
    applicationId = "cn.reading.reading_tracker"   // 占位式命名
    minSdk   = flutter.minSdkVersion               // 继承 Flutter 默认
    targetSdk = flutter.targetSdkVersion           // Flutter 3.24.5 默认为 34
    ...
}
buildTypes {
    release {
        signingConfig = signingConfigs.debug       // ← 使用 debug 签名
    }
}
```

四点问题：

1. **release 使用 debug 签名** —— Google Play 直接拒绝；且项目内**无任何 keystore / `key.properties`**。
2. **targetSdk 不达标**。据 Google Play 官方规定：**自 2026-08-31 起，新应用与应用更新必须以 Android 16（API 级别 36）或更高为目标**。今天是 2026-09-30，该要求**已生效**。当前继承 Flutter 3.24.5 的默认值（API 34），提交即被拦。
3. **只产出 APK**。Google Play 要求上传 **AAB（Android App Bundle）**，需改用 `flutter build appbundle`。
4. **包名 `cn.reading.reading_tracker` 是占位式命名**，非规范的反转域名。**上架后包名永久不可更改**，必须在首次提交前定稿。

补充问题：

- `android:label="阅读管理"` 硬编码中文，国际设备上将显示中文应用名。
- 应用图标仍是 **Flutter 默认图标**（`mipmap-*/ic_launcher.png` 仅 1.4 KB）。
- Android 13+（API 33+）读取相册需 `READ_MEDIA_IMAGES`；清单未声明任何媒体/相机权限，需在真机上逐路径验证 image_picker 行为（系统 Photo Picker 多数场景可免权限，但不能想当然）。

### P0-3　完全没有国际化（i18n）基础设施

这是面向国际市场的**第一阻断项**。

| 检查项 | 结果 |
|---|---|
| `flutter_localizations` 依赖 | **无** |
| `l10n.yaml` / `lib/l10n/` | **不存在** |
| `.arb` 资源文件 | **0 个** |
| `supportedLocales` / `localizationsDelegates` | **未配置** |
| 源码内中文字符出现次数 | **约 74,774 处** |
| `MaterialApp.title` | 硬编码 `'阅读管理'` |

派生问题：

- **分类受控词表为中文**（`lib/models/enums.dart` 的 `defaultCategories`：文学 / 经济 / 成长 / 心理…）。国际用户看到的是中文字符串，且统计图表的分类轴全部中文。
- `intl` 虽在依赖中，但**未用于日期/数字的本地化格式化**。
- 年度/月度等周期名称、AI 报告提示词与输出、错误提示、空态文案——全部中文。

### P0-4　工具链与依赖版本落后约两年

| 项 | 现状 | 影响 |
|---|---|---|
| Flutter SDK | 3.24.5（Dart 3.5.4） | 无法编译 targetSdk 36；不支持新的 Material 组件 |
| `google_mlkit_text_recognition` | 锁 `^0.13.0` | 最新为 **0.15.1（2026-02）**，要求 Dart ≥3.8 / Flutter ≥3.32 |
| `sqflite_common_ffi` | 锁死 `2.3.4+4` | 因 Flutter 版本被迫降级，属于被工具链倒逼的技术债 |

升级 Flutter 是解开 P0-1（iOS 15.5）、P0-2（API 36）、P0-4（ML Kit）**三项的公共前置**，应作为第一阶段的第一动作。

## 二、P1 — 商店合规必填项

### P1-1　无隐私政策、无用户协议、无数据安全表单

- Google Play 要求填写 **Data Safety** 表单并提供**隐私政策 URL**；
- App Store 要求填写 **App Privacy** 标签并提供隐私政策链接；
- 本 App 存在把数据发往第三方（用户自填的 LLM 端点）的行为，**必须披露**，否则属于虚假申报。

### P1-2　API 密钥明文存储

`lib/ui/settings_page.dart` 通过 `saveSetting()` 将 `weread_key`、`llm_key` **明文写入 SQLite 的 `settings` 表**：

```dart
await saveSetting(ref, 'weread_key', _wereadKey.text.trim());
await saveSetting(ref, 'llm_key',    _llmKey.text.trim());
```

微信读书 Key **等同身份凭证**（可读取用户完整书架、进度、笔记）。虽位于应用私有目录、未 root 设备相对安全，但仍应迁移到 `flutter_secure_storage`（Android Keystore / iOS Keychain）。这也是商店安全审查的加分项。

### P1-3　第三方数据流未充分披露

三条出境/出机路径需在隐私政策中逐条说明：

1. `WereadGateway` → `https://i.weread.qq.com`（中国境内服务，国际用户不可用）；
2. `LlmClient` → 用户自填端点，**上传聚合统计数据**（AI 报告）；
3. `LlmShelfParser.readImage()` → **上传整张书架截图的 JPEG** 到多模态模型。截图可能含个人信息，需**独立的明示同意**。

### P1-4　内容版权与数据源 ToS

元数据补全抓取 Google Books API、Open Library、微信读书书城。需确认：

- 各源的用户协议是否允许此种调用与二次展示；
- 封面图（`coverUrl`）的展示授权（种子数据中 `coverUrl` 已置 `null`，方向正确；但用户导入时仍会写入第三方封面 URL）。

## 三、P2 — 国际化与市场适配（"全国 + 国际"的核心缺口）

### P2-1　数据源高度中国特化，"亚马逊 / Kindle 等源尚未实现"

**这是最需要对齐预期的一点**：您提到"最初按个人使用对标，比如导入书籍，还有亚马逊、Kindle 等源"。经核查，**这些源目前并未实现**。实际已实现的数据源仅有：

| 来源 | 实现状态 | 国际可用性 |
|---|---|---|
| 微信读书官方网关 | ✅ 已实现（书架/进度/统计/搜索） | ❌ 仅中国境内用户可用 |
| 截图 OCR（掌阅/京东/文石） | ✅ 算法就绪 | ⚠️ 算法中文特化，对英文书架基本失效 |
| Notion CSV 导入 | ✅ Node 工具链实现 | ⚠️ 列名映射按中文场景定制 |
| Google Books / Open Library | ✅ 仅用于**元数据补全**，非书架导入 | ✅ |
| Amazon / Kindle、Goodreads、Apple Books、Kobo、豆瓣 | ❌ **均未实现** | — |

面向国际市场，需要新增至少 2–3 个主流源的适配器：

- **Goodreads** / **Hardcover** / **StoryGraph**：英文读者主流书架与进度数据；
- **Kindle / Amazon**：无官方公开 API，需评估"导入 Kindle 剪报 / 导出 CSV"路径；
- **Apple Books**、**Google Play Books**、**Kobo**：平台自带的阅读数据。

得益于既有的"统一 `Book` 模型 + adapter"架构（文档 §2 所述），新增源的边际成本可控——每个源只需写一个 adapter，上层 UI/统计/报告无需改动。**这是本项目最有价值的可扩展设计，应充分利用。**

### P2-2　OCR 算法为中文特化，对英文书架失效

`lib/import/shelf_ocr_parser.dart` 的核心判据包括：

- **百家姓姓氏表**判定作者行；
- **中文 UI 噪音词表**（书架、最近阅读、已读完、无限卡…）；
- **中文书名号**（《》）作为置信度加分项；
- 竖排书名、封面美术字的处理。

这些规则对**英文书架截图/拍照**几乎完全无效（英文用 `by Author`、`Title Case`、无书名号）。国际版需要一套并行的英文规则集（或改为基于版面几何 + 多模态模型的通用方案，弱化语种规则依赖）。

### P2-3　AI 提示词、报告、周期名称均为中文

`LlmClient.inferMetadata` / `generateReport` 的系统提示词与输出格式要求全部中文；统计周期的中文命名（年度/月度）亦需本地化。建议提示词按 locale 切换，并允许用户指定报告输出语言。

### P2-4　无云同步，跨设备迁移靠手动备份

当前为纯本地架构（这是正确的基础设计），跨设备只能通过 JSON 备份文件手动搬运。国际用户对"换手机数据全丢"高度敏感。路线图 P5（WebDAV / iCloud / Google Drive）尚未启动。

> 注：**无账号体系**在合规上是简化（无需处理账号注销与数据删除请求），但需在商店页面明确说明"数据仅存本地"，避免用户预期落差。

### P2-5　应用品牌与商店资产缺失

- 无正式产品名（现为 `reading_tracker` / "阅读管理"），
- 无图标设计、无商店截图（`test/goldens/` 已有 14 张界面图可复用为素材基础）、无 listing 文案与关键词。

## 五、建议的补齐路线

### 阶段一：打通发布链路（阻断项清零）

1. 升级 Flutter 至当前稳定版（≥3.32），同步放宽 `sqflite_common_ffi` 与 `google_mlkit_text_recognition` 版本约束；
2. Android：生成正式 keystore 与 `key.properties`，配置 release 签名，`targetSdk = 36`、`minSdk = 24`，产出 AAB；
3. 定稿**全球唯一包名**并替换 `applicationId`；
4. 补齐 iOS：`ios/` 工程、`Podfile`（`platform :ios, '15.5'`）、`Info.plist` 相机/相册用途声明、`PrivacyInfo.xcprivacy`、多语言声明；准备 macOS 构建环境；
5. 设计正式应用图标与应用名。

### 阶段二：合规与商店材料

6. 起草隐私政策与用户协议（覆盖三条数据出境路径），托管为公网 URL；

8. 密钥迁移至 `flutter_secure_storage`；

## 六、需要您确认的决策点

1. **首发市场**：是"先中国后国际"，还是"中英同步首发"？若先发中国，P0-3（i18n）可后置，P0-1/P0-2/P1 仍需先解决。

4. **国际数据源优先级**：Goodreads / Kindle / Apple Books 哪几个先做？
5. **是否引入云同步**：直接影响架构（需要后端与账号体系，合规工作量随之上升）。
6. **变现模式**：免费 / 内购 / 订阅？影响是否要引入应用内购买与相应的商店配置。
