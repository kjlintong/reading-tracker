## 四、本轮修正的 iOS 隐私清单缺陷（2026-10-01）

`app/ios/Runner/PrivacyInfo.xcprivacy` 原文件有**两处会直接导致上传被拒**的错误，
已全部修好（细节见 `store/privacy/app-store-app-privacy.md`）：

| 原内容 | 问题 | 现状 |
|---|---|---|
| `NSPrivacyCollectedDataTypeUserContent` | 不是合法的数据类型键 | 改为 `NSPrivacyCollectedDataTypePhotosorVideos` 与 `NSPrivacyCollectedDataTypeOtherUserContent`（注意键名里的 "or" 是小写） |
| `NSPrivacyAccessedAPICategoryFileManager` | **不属于**那五个法定类别之一 | 改为 `NSPrivacyAccessedAPICategoryFileTimestamp` |
| `0D5T.1` | 理由码不在任何类别允许列表内 | 改为 `CA92.1`（UserDefaults）与 `C617.1`（FileTimestamp） |
| `NSPrivacyAppBuiltInBrowserSupport` | 不是清单里存在的键 | 已删除 |

`NSPrivacyAccessedAPITypes` 只有**五个**合法类别（FileTimestamp / SystemBootTime /
DiskSpace / ActiveKeyboards / UserDefaults），理由码必须取自该类别的允许列表，
否则归档报 **ITMS-91055**；漏报必需的 required-reason API 则报 **ITMS-91053**。

## 五、待用户决策：ML Kit 性能数据声明

按 Google ML Kit 服务条款，输入数据（照片、书脊图像）**完全在设备端处理、
不会上传给 Google**，但：

> "The ML Kit APIs also send metrics about the performance and utilization
> of the APIs in your app to Google."

并明确开发者有义务告知用户。因此严格口径下应额外声明一项
**诊断数据 → 性能数据（Diagnostics → Performance Data）**。

- 隐私政策 `docs/06 §3.4` / `docs/07 第 4 条` **已经写明**这一点（含官方原文引用）。
- 但 `PrivacyInfo.xcprivacy` 目前只声明 **2 项**数据类型
  （`NSPrivacyCollectedDataTypePhotosorVideos`、`NSPrivacyCollectedDataTypeOtherUserContent`），
  **没有**这一项；`store/privacy/app-store-app-privacy.md` 里把它标为 ⚠️ 待定。
- 取舍：如实声明更稳妥（内容反正已经在隐私政策里公开了），
  但会让「本地优先、不收集数据」的卖点被削弱。**需要用户拍板。**
- 影响面：一旦采纳，要同时改 `PrivacyInfo.xcprivacy`（加第三个 dict）、
  App Store 的 App Privacy 表单第一栏勾选，以及
  `store/privacy/google-play-data-safety.md`（Play 侧本来就已按「共 3 项」写了，
  两边口径要对齐）。
