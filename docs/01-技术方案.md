# 个人阅读管理 App — 技术方案

> 目标：替代 Notion 手动维护，统一管理微信读书 / 掌阅精选 / 京东读书专业版 / 文石 / 图书馆纸质书的阅读情况，
> 支持截图与拍照导入、自动补全书籍元数据、大模型定期分析报告。
>
> 版本：v0.1（骨架落地） · 日期：2026-09-29

---

## 一、技术选型

| 层次 | 选型 | 理由 |
|---|---|---|
| 客户端 | **Flutter（Dart 3.5+）** | 一套代码覆盖 Android + iOS；官方支持 Windows / macOS / Linux 桌面端，后期加 Windows 程序无需重写；端侧 OCR 与本地 SQLite 生态成熟 |
| 本地存储 | **SQLite（sqflite）** | 本地优先，无账号无网络也能完整使用；不需要代码生成步骤，clone 即可运行 |
| 端侧 OCR | **Google ML Kit Text Recognition** | 离线可用、免费、中英文识别效果好，Android 走 ML Kit、iOS 走 Apple Vision，Flutter 插件统一 API |
| 元数据补全 | 微信读书官方网关 → Google Books → Open Library → LLM 兜底 | 链式降级，任一不可达不影响导入流程 |
| 大模型 | **OpenAI 兼容协议**（DeepSeek / 通义 / 智谱 / Ollama 等） | 不绑定厂商，用户自填 Key，App 不代持任何密钥 |
| 状态管理 | Riverpod | 轻量、可测试 |

### 为什么选 Flutter 而不是 React Native

你的需求里明确有"后期可以添加 windows 程序"。Flutter 官方提供 Windows 桌面端支持（社区成熟度高于
`react-native-windows`），且 Android/iOS/Windows 共用一套 Dart 代码与一套数据层。
本项目的 `sqflite_common_ffi` 已在桌面端做了适配，后期加 Windows 只需配置桌面端窗口尺寸与打包。

## 二、总体架构

```
① 采集层                    ② 归一化管道              ③ 本地数据层            ④ 应用层
┌──────────┬──────────┐
微信读书    截图OCR       →   去重 · 元数据补全   →   SQLite（离线可用）  →  书架与进度
（官方接口） （掌阅/京东/文石）      · 分类                · 图片本地存         统计看板
拍照识别    CSV导入
（纸质书/图书馆）（Notion历史）                                              AI 报告
└──────────┴──────────┘
```

**单一数据模型是地基**：所有导入源先转成统一的 `Book` 结构再落库。新增一个平台只需写一个 adapter，
上层 UI、统计、AI 报告完全不用动。

| 来源 | 方案 | 状态 |
|---|---|---|
| **微信读书** | **官方 Agent 网关**：`POST https://i.weread.qq.com/api/agent/gateway`，`Authorization: Bearer <WEREAD_API_KEY>` | ✅ **已实测端点可达**（返回 401 表示仅缺鉴权）。可拿书架、阅读进度、笔记划线、阅读统计、书城搜索 |

| 文石 Boox | 截图 OCR 为主 | ⚠️ 设备端有 ONYX 账号同步与"阅历"统计（网页端 send2boox.com 可看），但**无公开 API** 供第三方读取，故走截图 |
| 图书馆纸质书 | 拍照识别封面/书脊 → 补全元数据 | ✅ 可行 |
| Notion 历史 | 导出 CSV → 导入器映射 | ✅ **已实现并验证** |

### 关于微信读书官方接口（重要发现）

微信读书开放了官方 Skill 网关，这比社区流传的 cookie 抓取方案稳定且合规得多。
获取 Key：微信扫码打开 `https://weread.qq.com/r/weread-skills`，复制页面上的 `wrk-` 开头 Key。

常用接口：

```bash
# 书架
curl -X POST "https://i.weread.qq.com/api/agent/gateway" \
  -H "Authorization: Bearer $WEREAD_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"api_name":"/shelf/sync","skill_version":"1.0.3"}'

# 阅读统计
-d '{"api_name":"/readdata/detail","mode":"overall","skill_version":"1.0.3"}'

# 书城搜索（用于元数据补全）
-d '{"api_name":"/store/search","keyword":"三体","scope":10,"count":5,"skill_version":"1.0.3"}'
```

**这个接口同时解决了中文书籍元数据问题**——书城搜索可返回作者、出版社、简介、分类、封面，
比 Google Books 的中文覆盖好得多。

## 四、数据模型

统一模型定义在 `app/lib/models/book.dart`（Dart）与 `tools/lib/schema.mjs`（Node），两端字段一一对应。

### Book（书籍）

| 分组 | 字段 |
|---|---|
| 标识 | `id`, `title`, `subtitle`, `authors[]`, `translators[]`, `isbn13` |
| 出版 | `publisher`, `publishedAt`, `pageCount`, `wordCount`, `language` |
| 分类 | `categoryPrimary`, `categoryPath`, `tags[]` |
| 内容 | `description`（简介）, **`summary`（摘要，Notion 原有）**, **`review`（读后感）**, `highlights`（摘抄） |
| 来源 | `source`（平台）, `sourceBookId`, `sourceUrl`, `coverUrl` |
| 状态 | `status`（想读/在读/已读/弃读/借阅中/暂搁）, `progressPercent`, `currentPage`, `rating` |
| 纸质书 | `format`, `borrowedFrom`, **`dueAt`（图书馆应还日期）**, `rereadCount` |
| 兜底 | **`extra{}`** — 保留源系统自定义字段，迁移零丢失 |

### 其他表

- `reading_logs` — 阅读日志（日期、时长、页码区间），用于统计时长与连续天数
- `notes` — 划线 / 想法 / 书评
- `import_batches` — 导入批次，可回溯、可整批回滚
- `llm_reports` — AI 报告历史
- `settings` — 用户配置（API Key 等，仅存本地）

### 去重策略

指纹优先级：`ISBN > 书名+首位作者`。命中重复时**只补空缺字段，绝不覆盖用户已填内容**
（用户手填的数据可信度高于任何数据源）。

## 五、截图 OCR 书名提取算法

这是本项目的核心差异化能力。书架截图 OCR 出来的是夹杂 UI 文字、作者名、进度条、时间戳的
混合文本，需要清洗。算法在 `tools/lib/ocr_clean.mjs`（参考实现，含测试）与
`app/lib/import/shelf_ocr_parser.dart`（端侧实现）。

处理流程：

1. **硬过滤** — 进度（`45%` / `读至 45%`）、日期、时间、数量（`共 128 本`）、纯数字、链接
2. **UI 噪音词表** — 覆盖微信读书 / 掌阅 / 京东 / 文石四家的常见界面文案（书架、最近阅读、已读完、无限卡…）
3. **作者剥离** — 必须**命中百家姓姓氏表**才判为作者。这是关键设计：否则「筝的人」这类
   被 OCR 拆断的书名残片会被误吞，导致书名残缺
4. **置信度打分** — 长度、是否含书名号、是否中文、是否相邻行
5. **断行合并** — 条件刻意保守（前行 ≤4 字、后行 ≤3 字、只允许合并一次）。
   把两本书错误粘成一本，比漏合并糟糕得多
6. **用户确认页** — 默认勾选置信度 ≥60% 的，低置信度需手动勾选

**设计取向：宁可多召回，不可漏召回。** 误判由用户在确认页一键剔除（可见、可控）；
漏掉则用户完全无感知（不可控）。

## 九、工具链用法（立即可用，无需 Flutter）

### 1. 迁移 Notion 历史数据

```bash
# 从 Notion 导出 CSV：数据库右上角 ··· → Export → CSV
cd reading-tracker/tools
node notion-import.mjs 你的导出.csv --out books.json
```

会打印列映射报告，未识别的列自动存入 `extra`，不丢数据。

### 2. 批量补全元数据

```bash
export WEREAD_API_KEY=wrk-xxx                      # 扫码获取，中文书首选
export LLM_API_KEY=sk-xxx                          # 可选，兜底补全
node enrich.mjs books.json --out enriched.json --llm
```

### 3. 跑测试

```bash
node test/smoke.mjs      # 28 项
node test/ocr.test.mjs   # 26 项
```
